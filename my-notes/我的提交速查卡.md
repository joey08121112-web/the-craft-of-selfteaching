## 1. 每天的收尾动作：三行命令（就是李笑来说的第 6 步）

```bash
git add .
git commit -m "在这里写一句话：今天学到哪、做了什么"
git push
```

- `git add .` —— 把今天改过的所有文件打包装进「暂存区」（相当于勾选要提交的改动）
- `git commit -m "..."` —— 正式记录一次，引号里的话会永远留在历史里，**写人话**，例如：
  - `"学完 Part.1.E.2，把每个运算符都敲了一遍"`
  - `"Part.1.E.4 函数：自己写了第一个带参数的函数"`
- `git push` —— 把记录上传到 GitHub 上你的 Fork（第一次推新分支用 `git push -u origin 分支名`，之后就只写 `git push`）

push 成功 = 这条学习记录永久落在你的 GitHub 仓库里，可查可回溯 = 工作证明 +1。

## 4. origin 和 upstream 是什么（upstream 已于 2026-09-13 配好）

一个 git 仓库可以登记多个「远程仓库」地址，各起一个名字：

```bash
$ git remote -v
origin    https://github.com/joey08121112-web/the-craft-of-selfteaching.git   # 你的 Fork：push 到这里
upstream  https://github.com/selfteaching/the-craft-of-selfteaching.git       # 李笑来的原书：只用来拉取更新
```

- **origin** = 你的 Fork。`git push` 默认推到这里——你的工作证明落在你这。
- **upstream** = 原书仓库。你对它没有写权限，它的作用只有一个：当李笑来更新了书，你可以把更新拉下来。

**为什么之前只有 origin 也能过日子**：GitHub 网页上你 Fork 页面的 **Sync fork → Update branch** 按钮做的是同一件事。配了 upstream 只是让你多一种命令行做法：

```bash
git fetch upstream          # 去原书仓库看看有没有新提交
git switch master
git merge upstream/master   # 把原书的更新合并进本地 master
git push                    # 推给自己的 Fork，三方一致
```

就这本书而言更新频率很低（2026 年全年没几次），**记住网页按钮就够了**，命令行方式备查。

## 5. 常见问与答

- **Q：我天天 push 会不会把原书仓库搞乱？**
  不会。你所有 push 都只落在你自己的 Fork，李笑来那边完全看不到、不受任何影响。只有当你主动发 Pull Request 且他点合并时，改动才会进原书。
- **Q：commit 的邮箱要求？**
  已配好 `joey08121112@gmail.com`。只要这个邮箱在你的 GitHub 账号（Settings → Emails）里验证过，提交就会挂到你的头像下；没验证的话去 GitHub 点一下验证邮件即可。
- **Q：Jupyter 提示选内核选什么？**
  选 `deeplearning`（你机器上现成的 Python 内核）或 `Python 3 (ipykernel)` 都可以。
- **Q：命令敲错了报错怎么办？**
  把报错原文发给 AI 助手即可，git 的报错信息很啰嗦但很诚实，90% 的情况一句 `git status` 就能自救。
